# User Stories и критерии приёмки (User Stories & Acceptance Criteria)

Данный навык преобразует функциональные требования в практичные задачи для бэклога с четкими критериями сдачи.

## Шаблон User Story
```text
Как [роль пользователя],
Я хочу [действие / функциональность],
Чтобы [бизнес-ценность / результат].
```

## Принципы INVEST
- **I (Independent)**: задача независима от других историй в спринте.
- **N (Negotiable)**: детали реализации открыты для обсуждения.
- **V (Valuable)**: приносит осязаемую ценность пользователю.
- **E (Estimable)**: объем работ поддается оценке.
- **S (Small)**: задача укладывается в рамки одной итерации.
- **T (Testable)**: результат однозначно проверяем.

## Критерии приёмки (Given-When-Then / BDD)
```gherkin
Сценарий: Успешное выполнение действия
  Дано (Given): начальное состояние системы и авторизованный пользователь
  Когда (When): пользователь совершает ключевое действие
  Тогда (Then): система обновляет состояние и отображает подтверждение
```
